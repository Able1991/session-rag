# session-rag: поиск по истории сессий Claude Code

**Что это.** Локальный MCP-сервер `history`. Он даёт агенту в любом проекте доступ ко всей прошлой работе: разговорам, командам и их выводу, CLAUDE.md, памяти и документам проекта. Новая сессия перестаёт начинать с нуля: на вопрос «как мы чинили балансировщик в прошлом месяце» агент находит настоящую команду и вывод, а не придумывает.

## Установка за три команды

Нужны [uv](https://docs.astral.sh/uv/) и Python 3.11+, macOS или Linux.

```bash
git clone https://github.com/Able1991/session-rag && cd session-rag && uv sync
uv run session-rag index          # первая сборка индекса, несколько минут
claude mcp add --scope user history -e HF_HUB_OFFLINE=1 -- "$PWD/.venv/bin/session-rag" serve
```

Чтобы индекс обновлялся сам:

```bash
uv run session-rag schedule install            # переиндексация раз в 30 мин (launchd / systemd)
uv run session-rag schedule install --serve    # плюс один общий сервер на машину вместо копии на каждую сессию
```

С общим сервером регистрируйте его как HTTP: `{"type": "http", "url": "http://127.0.0.1:47817/mcp"}`. При десятке открытых сессий это экономит гигабайты памяти.

Добавьте в `~/.claude/CLAUDE.md` правило, чтобы агент сам вспоминал про инструмент:

> Если вопрос касается прошлой работы (как чинили, какой IP, путь или команда, что решили), сначала вызывай `search_history` и передавай в `also` 2–3 другие формулировки, потом `get_context(id)`. Grep по транскриптам только если поиск ничего не нашёл.

## Инструменты агента

| инструмент | что делает | скорость |
|---|---|---|
| `search_history(query, also, k, since, roles, project)` | Ищет конкретные факты. В `also` агент передаёт другие формулировки, в том числе на другом языке. `project`: текущий по умолчанию, имя другого проекта или `"all"` | 30 мс – 1 с |
| `get_context(id)` | Показывает сообщения вокруг найденного куска | ~5 мс |
| `knowledge(name, also, project)` | «Что мы знаем про X»: профиль сущности, связи, свежие факты. Работает, только если для проекта собран граф знаний | ~0,2 с |

## Как устроено

1. **Индексация.** Claude Code пишет каждую сессию в `~/.claude/projects/<папка>/<id>.jsonl`. Индексатор дочитывает файлы с запомненного места и режет их на куски: реплика пользователя, ответ ассистента, вызов инструмента (команда с описанием), результат (до 1200 знаков). Проект определяется по рабочей папке сессии.
2. **Секреты.** Перед записью ключи, токены, пароли, JWT и логины в URL заменяются на `***`. Маскировка по шаблонам, поэтому сам индекс лежит с правами 600: обращайтесь с ним как с транскриптами.
3. **Хранение.** Одна база SQLite `~/.local/share/session-rag/index.db`: полнотекстовый индекс FTS5 со стеммингом для русского и английского, векторы sqlite-vec, таблицы графа знаний.
4. **Поиск.** BM25 отдельно по каждой формулировке, слияние списков (RRF), затем выше поднимаются куски, где есть больше слов из запроса. Векторы подключаются, только когда по словам кандидатов мало. Ответ: до k кусков по 900 знаков с номером, проектом, временем и ролью.
5. **Обновление.** По расписанию и хуком при закрытии сессии. Ответ агента из одной сессии через несколько минут находится из другой.

## Граф знаний (по желанию)

`session-rag knowledge build <проект>` отдаёт каждый закончившийся день сессии в `claude -p --model haiku`. Оттуда приходят сущности, факты с точными значениями и связи, каждый факт со ссылкой на исходный кусок. Включается флагом `knowledge = true` у проекта в `~/.config/session-rag/config.toml`.

Учтите: это единственная часть, которая отправляет текст наружу (в Anthropic через ваш `claude`), и она тратит вызовы Haiku. На вопросах «что знаем про X» граф находит около 40% нужных фактов против 12% у обычного поиска, но на практике такие вопросы задают редко.

## Цифры

- **Поиск фактов** (30 вопросов, написанных вручную, проект по инфраструктуре): нужный ответ первым в 67% случаев, у grep в 37%. В первых трёх в 87%.
- **Объём ответа:** около 2 КБ вместо сотен килобайт JSON, которые возвращает grep по транскриптам.
- **Индексация:** 6,7 ГБ транскриптов за 6,5 минуты с нуля, дочитка новых сообщений за пару секунд.
- **На практике** (3 недели, 16 проектов): около 20 вызовов в день, медиана поиска 0,7 с.
- **Не помогли:** векторный поиск сам по себе, реранкер, дневные дайджесты. Подробности в [README](../README.md).

## Полезные команды

```bash
session-rag search "ошибка при деплое" -k 5     # из терминала, текущий проект
session-rag search "terraform state lock" --all
session-rag projects                             # найденные проекты и число кусков
session-rag stats                                # как часто агенты пользуются, задержки
session-rag eval my-cases.toml                   # качество поиска на ваших вопросах
```

## Известные слабые места

- **Сессия, начатая до запуска сервера,** не видит `history`. Поможет `/mcp` и переподключение.
- **В выдачу попадает текущая сессия.** Это шум, но и плюс: свежее решение из соседней сессии тоже находится.
- **Код не индексируется намеренно.** Для кода grep, LSP и чтение файлов всегда актуальны, а индекс устаревает с каждым коммитом.
